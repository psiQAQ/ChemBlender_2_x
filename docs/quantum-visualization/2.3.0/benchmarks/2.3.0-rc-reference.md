# 2.3.0 RC reference performance baseline

## Scope and status

This document records the 2026-07-31 Windows reference observation for
Performance and UX Hardening Task 2. The local experience gates use the
`p95_seconds` value, never a best single sample. This is **not** a complete
reference qualification: the current Task 1 harness intentionally reports
Blender-only and future cases as `Not Run`, and the incomplete report is not
accepted by `compare_performance_report()`.

## Budget and regression policy

`ChemBlender/benchmarks/budget.json` is schema `1.0` and maps the six
approved limits above to their Task 1 case names. Every hard local gate is
`p95_seconds`; missing case data, `Not Run`, failure, non-finite timing,
unknown case, wrong scale, or wrong declared cache state raises `ValueError`.

CI compares `p95_seconds` only when candidate and baseline contain every
budget case at the same scale and the same per-case `cold`/`hot` state. It
also requires equal `cpu_count`, `machine`, `platform`, `processor`, Python
implementation, and Python version. The interpreter path is deliberately not
part of this compatibility signature because controlled CI checkout paths are
not a performance property.

The trend regression threshold is **15%**. This is a Task 2 review policy,
not a claim of an earlier approved percentage: it allows bounded noise in
controlled repeated measurements while remaining more conservative than a
20% tolerance. A hard budget breach or a trend increase greater than 15%
returns `passed: false`; any absent, non-finite, cache, scale, or environment
mismatch fails closed. Changing a baseline or threshold requires explicit
review evidence.
