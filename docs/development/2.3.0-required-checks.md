# 2.3.0 Required Checks

This is the 2.3.0 merge and release-check contract.  Check names below are the
current GitHub Actions workflow/job display names, not proposed workflow names.

## Checks and ownership

| Check | Current trigger and responsibility | Failure owner |
| --- | --- | --- |
| `extension-package / native-core` | Runs on every pull request; on pushes to `main`, `feat/2.3.0-wave3-exchange-mol2-pdb-pqr`, and `v*` tags; and manually. It is the 10-minute Windows standard-library gate for dependency/fixture, documentation, repository, artifact, release and committed-format contracts plus `compileall`. It owns docs/contracts coverage. | Change author fixes the affected source, test, documentation, or committed formatting. |
| `extension-package / package` | Runs after `native-core`. It downloads pinned Blender 5.1.2 and RDKit/Gemmi wheels, runs the Blender suite, validates/builds, cold-installs, smokes the extension, verifies the five-file package artifact, and is the only authoritative package upload. | Packaging/release owner and the change author fix dependency, build, install, artifact-budget, or lifecycle failures. |
| `optional-qc-core / cclib` | Runs on every pull request, pushes to `main`, and manually. It installs the locked CPython 3.13 cclib environment, verifies pinned fixtures, and rejects every non-ordinary result in `tests.test_cclib_adapter`. | cclib adapter/fixture/lock change owner. |
| `optional-qc-core / iodata` | Runs on every pull request, pushes to `main`, and manually. It applies the same zero-skip rule to the locked CPython 3.13 IOData environment and `tests.test_iodata_adapter`. | IOData adapter/fixture/lock change owner. |
| `optional-qc-core / gbasis` | Runs on every pull request, pushes to `main`, and manually. It uses CPython 3.12 with NumPy 1.26.4 and rejects non-ordinary results in `tests.test_wavefunction_grid` and `tests.test_wavefunction_observables`. | GBasis/IOData wavefunction adapter, fixture, or lock change owner. |
| `extension-release / verify` | Manual only, from the default branch, after an annotated tag has one successful exact-SHA package artifact. With `publish=false` it is read-only: it selects and re-verifies that artifact and its tagged changelog. It is a release dry-run, not a pull-request status check. | Release manager fixes tag, metadata, artifact provenance, or changelog mismatch; do not publish while it fails. |

`extension-release / publish` is deliberately excluded from required checks: it
needs explicit publication authorization and the protected `release`
environment.

## Optional-backend change rule

The workflow currently schedules all three optional jobs for every pull
request.  The following table assigns the review and failure responsibility;
it does not claim that unaffected jobs are skipped.

| Change | Required optional evidence |
| --- | --- |
| `ChemBlender/core/cclib_adapter.py`, cclib fixtures/tests, or `cclib-py313.txt` | `optional-qc-core / cclib` |
| `ChemBlender/core/iodata_adapter.py`, IOData fixtures/tests, or `iodata-py313.txt` | `optional-qc-core / iodata` |
| GBasis/grid/observable code or fixtures, `gbasis-py312.txt`, or shared IOData wavefunction input | `optional-qc-core / gbasis` |
| `optional-qc-core.yml`, `run_required_integration.py`, shared runner policy, or all optional locks | `cclib`, `iodata`, and `gbasis` |
| Documentation-only changes unrelated to an optional-backend contract | No additional optional ownership; `native-core` remains the documentation/contract gate. |

## Recommended protection, not applied

For `main`, repository administrators should require these current contexts:

- `extension-package / native-core`
- `extension-package / package`
- `optional-qc-core / cclib`
- `optional-qc-core / iodata`
- `optional-qc-core / gbasis`

Require the branch to be current before merge and keep the release dry-run
outside branch protection because `extension-release / verify` is dispatch-only.
This is a recommendation only: no GitHub repository setting has been changed.
Applying or changing branch protection requires a separately authorized GitHub
operation.

For the release procedure, see [Branch and Release Workflow](branch-and-release.md).
