# Upgrade to ChemBlender 2.3.0

This guide covers an installed ChemBlender 2.2.0 Extension and projects saved
as a `.blend` plus `.cbq` pair. For scenes created by the older direct-object
workflow, also follow the [legacy scene migration guide](../user/legacy-migration.md).

## Before installing

1. In the old version, save the project and close every Blender window that
   uses ChemBlender.
2. Make a manual backup of both `project.blend` and the complete
   `project.cbq/` directory. Keep the pair together and preserve their relative
   layout.
3. Download the ZIP and matching `.sha256` file from the
   [official Release page](https://github.com/psiQAQ/ChemBlender_2_x/releases).
   Do not substitute an unreviewed CI artifact or a ZIP from another source.
4. Verify the SHA-256 before installation. Set `$version` to the exact Release
   version you downloaded, including a prerelease suffix when applicable.

```powershell
$version = '2.3.0'
$zip = Get-Item -LiteralPath ".\chemblender-$version.zip"
$checksum = Get-Item -LiteralPath ".\chemblender-$version.sha256"
$record = (Get-Content -LiteralPath $checksum.FullName -Raw).Trim()
if ($record -notmatch '^(?<digest>[0-9A-Fa-f]{64})\s+\*?(?<name>\S+)$') {
  throw 'Invalid checksum record'
}
if ($Matches.name -ne $zip.Name) { throw 'Checksum names another package' }
$actual = (Get-FileHash -Algorithm SHA256 -LiteralPath $zip.FullName).Hash
if ($actual -ne $Matches.digest) { throw 'ChemBlender ZIP SHA-256 mismatch' }
```

## Install from a cold process on Windows

RDKit and Gemmi contain native DLLs. Windows can keep those DLLs locked after
an extension has been loaded, so an in-process overwrite is not a reliable
upgrade test.

1. Disable the old ChemBlender Extension, save Blender preferences, and exit.
2. Confirm no other Blender process has the project or extension loaded.
3. Start a cold Blender process and install the verified ZIP through Blender's
   Extension installation UI into the `user_default` repository.
4. Exit, start another cold Blender process, and verify that ChemBlender is
   enabled before opening the working copy of the project.

Do not copy the package into a legacy add-on directory and do not install its
wheels into Blender's global Python environment. The supported base remains
Blender 5.1+ on Windows x64.

## Sidecar schema upgrade

ChemBlender 2.3.0 writes `.cbq` manifest and project schema version `1.0`.
When a valid v0.1 or v0.2 sidecar is opened, its integrity is checked first and
the project is upgraded in memory. Opening it does not modify the old sidecar.
Entity UUIDs, scientific arrays and provenance retained by the migration stay
attached to the migrated project.

Before the first 2.3 save, keep the manual backup made above. Prefer **Save
As** to a new basename such as `project-2.3.blend`; ChemBlender then publishes
the corresponding `project-2.3.cbq/` in v1 and links all scenes to the verified
sidecar. Reopen the new pair and confirm that the project is Connected before
retiring the old copy.

Publication uses a same-directory staging tree and an internal publication
backup while replacing an existing sidecar. That internal publication backup
is normally removed after success and is not a user restore point. If
publication fails, stop and preserve any reported temporary or backup path for
diagnosis rather than deleting it.

An unknown format, unknown/newer schema, invalid manifest hash, mismatched
project UUID or invalid array will fail closed. ChemBlender does not adopt the
candidate by filename and does not repair it by silently discarding fields.
See [Project and sidecar](../user/project-sidecar.md) for Missing, Mismatch,
Incompatible and Invalid link states.

## Roll back to 2.2.0

ChemBlender cannot downgrade a sidecar saved as v1 for use by 2.2.0. To roll
back:

1. Close all Blender processes.
2. Reinstall a separately verified official 2.2.0 package from a cold process.
3. Restore both members of the same pre-upgrade `.blend`/`.cbq` backup pair.
4. Open that restored pair; do not mix a 2.2 `.blend` with a 2.3-created
   sidecar.

If the pre-upgrade pair is unavailable, keep the 2.3 files unchanged and seek
recovery/export help. Renaming a v1 directory or editing its manifest does not
make it a 2.2 sidecar.
