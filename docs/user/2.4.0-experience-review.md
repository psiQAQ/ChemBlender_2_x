# ChemBlender 2.4.0 人工体验检阅

这份清单用于观察真实使用体验，不重复自动化资格测试。请从公开
`v2.4.0` Release 安装包开始，按顺序完成任务，并记录实际看到的界面、反馈和
恢复路径。发现问题时 **do not implement**：先记录证据，后续再建立独立优化
目标。

- 输入文件名称、来源和是否可公开：

删除日常项目或覆盖唯一的 `.blend` / `.cbq` 数据。

## 检阅方式

每个任务先独立尝试，不阅读开发文档；遇到停顿后再查看对应用户指南。重点
观察：入口是否容易发现、术语是否能理解、等待时是否有反馈、错误是否可恢复、
以及下一步是否明确。不要把“最终完成”当作唯一通过条件。

| ID | Workflow | 操作 | 主要观察点 |
| --- | --- | --- | --- |
| UX01 | Install | 从公开 Release 安装 `chemblender-2.4.0.zip` 并启用 | 安装入口、依赖说明、成功反馈、是否需要重启 |
| UX02 | First launch | 不看文档，在 Blender 中找到 ChemBlender | 面板可发现性、首屏信息层级、最明显的下一步 |
| UX03 | Quick Import / Import Preview | 导入一个简单 XYZ 或 SDF，检查 Preview 后确认 | reader/quality/冲突/归组是否能理解，确认与取消是否明确 |
| UX04 | Structure / Volume / Surface | 导入一个 Cube，检查默认 Structure、Volume 或 Surface | 数据集选择、单位/符号、生成进度、视图与科学数据关系 |
| UX05 | Project Browser | 按 Source/Data 浏览、搜索、过滤并选择实体 | 层级、分页、选中状态、诊断与操作区的对应关系 |
| UX06 | Export | 从 Project Browser 导出一个支持格式 | 格式入口、目标实体、loss preview、确认、文件位置和完成反馈 |
| UX07 | save and reopen | 保存 `.blend`，关闭 Blender，再 reopen 项目 | `.blend`/`.cbq` 配对是否清楚，重开后选择和视图是否恢复 |
| UX08 | Cancel | 在导入或导出中取消一次操作 | 是否能看到取消状态、何时可以安全开始下一任务、是否残留半成品 |
| UX09 | recover | 制造一个可恢复错误，例如暂时移动测试 `.cbq` 后重开 | 错误解释、Relink/Verify/Diagnostics 入口、恢复后数据是否一致 |

## Severity

| Severity | 判断标准 |
| --- | --- |
| Blocker | 无法完成核心任务，或存在数据丢失/误导风险，且没有合理恢复路径 |
| Major | 可以绕过，但关键入口、状态或科学含义明显难以理解 |
| Minor | 局部文案、布局或反馈造成可重复的额外操作 |
| Suggestion | 不影响完成任务，但有明确证据表明另一种呈现更顺畅 |

## Finding 模板

复制以下模板，每个独立问题记录一份：

```markdown
### UX finding: <short title>

- Workflow ID:
- Environment:
- Severity: Blocker / Major / Minor / Suggestion
- Reproducibility: Always / Intermittent / Once
- Input/source:
- Preconditions:
- Steps:
  1.
- Expected result:
- Actual result:
- Evidence: screenshot, short recording, console excerpt or saved test pair
- Workaround:
- Scientific/data risk:
- First improvement idea (optional):
```

保持步骤最小化，隐藏私人路径和未公开数据。若问题涉及崩溃或项目链接，请先复制
测试文件再复现；不要在唯一项目上尝试破坏性恢复。

## 检阅结束

完成后汇总：

- 各 Workflow 是否完成及耗时；
- 需要查看文档或他人帮助的节点；
- Blocker / Major / Minor / Suggestion 数量；
- 最容易误解的三个术语或状态；
- 最值得优先优化的一条完整用户路径。

这些观察将作为后续 UX 优化目标的输入。整理阶段只收集和归类，不修改插件
行为、Release 或现有科学数据契约。
