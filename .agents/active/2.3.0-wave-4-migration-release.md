- RC后无新范围。

- Release只使用exact-tag成功artifact，不重建。

## Task 5 Pre-cleanup Caller Inventory (2026-07-31)

This is the proof snapshot used before Task 6. Task 6 subsequently removed
the zero-caller parser/export entries recorded below; the completed-task
evidence under the Execution Cursor is authoritative for the current tree.

- `scaffold.py`: the visible legacy `File`, `SMILES`, `PubChem` controls use
  `MESH_OT_SCAFFOLD_BUILD.execute()`. File covers CIF/POSCAR/CONTCAR and now
  reaches Quick Import; SMILES/preset creates an `ImportRequest`; PubChem
  stages an owned SDF before the same Quick Import boundary. At that trusted
  host boundary, every preview/materialization rechecks current session
  ownership, owned root, same-token metadata, strict CID URL and actual source
  SHA-256, then attaches deterministic existing `ProvenanceRecord` evidence;
  generic canonical parameters remain reader-neutral. The retained
  compatibility tail at `read.read_Cryst()` and `read.read_MOL()` is
  unreachable from those three current UI choices and remains for Task 6.
- `crys_utils.py`: direct legacy scaffold writers are `chem.supercell`,
  `chem.add_unit_cell`, `chem.add_crys_scaffold`, `chem.add_coordpolyhedra`,
  `chem.add_dummy`, and `chem.duplicate_symmetry`. `CRYSTAL_PT_TOOLS` hides
  its old controls for a unified Structure View, and each direct writer
  rejects that view with the Apply Scientific Edits diagnostic.
- `read.py`: `read_MOL()` retains the compatibility-only direct
  `download_sdf_from_pubchem()` branch; `read_Cryst()` retains the old
  `read_cif()`/`read_poscar()` parser path. None is a Task 5 UI action.
- `output.py`: `xyz_block()` has one production caller,
  `ui/scientific_edit.py._write_xyz()`, as the scientific-edit derived-XYZ
  helper; MOL/SDF/CIF/POSCAR block helpers remain compatibility helpers. The
  visible `chem.molecule_output` and `chem.update_cif_from_mesh` IDs now
  forward to the unified export and scientific-edit roots.
- `mesh.py`: `scaffold_to_mol()` remains the legacy editing/optimization
  boundary at its existing callers; no Task 5 deletion or parser rewrite is
  authorized.
